## 1.1. From Markov Chain to Hidden Markov Model (HMM)

### a. What is Markov Chain?

Imagine you want to predict the weather in a small town. You might simplify the possibilities to just two states: "Sunny" and "Rainy". 

You start observing the weather for several days and notice a pattern:

If it is Sunny today, there’s a 90% chance it will be Sunny tomorrow, but only a 10% chance it will be Rainy.

If it is Rainy today, there’s a 50% chance it will be Rainy tomorrow, and a 50% chance it will be Sunny.

This sequence of probabilities, where the weather tomorrow depends only on the weather today, is a classic example of a **Markov Chain**.

The key point is the **Markov Property** (or "memoryless property"). What is that?

The next state depends **only on the current state**, not on the sequence of states that came before it.

Mathematically, if $$S_t$$ represents the state at time $t$, the Markov Property is defined as:

$$P(S_{t+1} | S_t, S_{t-1}, ..., S_1) = P(S_{t+1} | S_t)$$

In our weather example:

State Space: {Sunny, Rainy}

And we have the Transition Probabilities:

* P(Sunny tomorrow | Sunny today) = 0.9

* P(Rainy tomorrow | Sunny today) = 0.1

* P(Sunny tomorrow | Rainy today) = 0.5

* P(Rainy tomorrow | Rainy today) = 0.5

If we make all of these probability a matrix, this matrix would be called the **Transition Matrix $$A$$**:

$$A = \begin{bmatrix} 0.9 & 0.1 \\ 0.5 & 0.5 \end{bmatrix}$$

Where the rows represent the current state (Sunny, Rainy) and the columns represent the next state (Sunny, Rainy). Each row sums to 1.

### b. From Markov Chain to Hidden Markov Model (HMM)
So what is the relation between Markov Chain and Hidden Markov Model? Well, turn out life is rarely that simple, we cannot always be able to observe the states we want directly in order to predict the future. So that is when our observable state become a hidden state. Let's continue with another example.

Instead of being able to directly observing the weather, let's say you are inside a windowless room and cannot see the sky. However, you have a friend who lives outside. Every day, your friend tells you whether they carried an Umbrella, a Bike, or just walked with no object.

So now, you can't observe the weather directly. But you can observe the friend's actions. So turn out, if we are able to observe the directly, we can use Markov Chain to model the weather. But since we cannot observe the weather directly, instead we have to observve something else that relates to the weather in order to infer the weather. That is when we need to use Hidden Markov Model. 
* The **Hidden** in Hidden Markov Model refers to the **hidden states**, which are the states that we cannot observe directly. 
* The **Observation** in Hidden Markov Model refers to things that we can directly observe (or given as inputs), so that we can use them to infer the hidden states.

Here is the clearer scenario:

* If it is Sunny, your friend is likely to go for a Walk (0.7) or ride the Bike (0.2). It's unlikely they bring an Umbrella (0.1).

* If it is Rainy, they will definitely bring an Umbrella (0.6). They might ride the Bike (0.3) (in a raincoat) or Walk (0.1) if they have no choice.

This setup creates a **Hidden Markov Model**:

The actual weather (Sunny/Rainy) is the **Hidden State**. You can't see it.

The friend's action (Umbrella/Bike/Walk) is the **Observable Emission**. You can hear it.

So earlier in the Markov Chain example, we have the transition matrix $A$:

$$A = \begin{bmatrix} 0.9 & 0.1 \\ 0.5 & 0.5 \end{bmatrix}$$

which define the connection between this current state to the next state (or between the current **hidden state** to the next **hidden state** in the HMM case). 

Now, in the HMM section, we have another matrix which define the connection between the **hidden states** and the **observable emissions**. This matrix is called the **Emission Probabilities** (or Output Probabilities) $$B$$.

$$B = \begin{bmatrix} 0.1 & 0.2 & 0.7 \\ 0.6 & 0.3 & 0.1 \end{bmatrix}$$

where rows correspond to the Hidden States (Sunny, Rainy) and columns correspond to the Observations (Umbrella, Bike, Walk).

> So for the conclusion, the HMM is an extension of the Markov Chain where we don't observe the states directly. We only observe outputs generated by those states.

# 2. The core theory - Math behind HMM
## 2.1. The Triplet Parameters (A, B, $$\pi$$)
To understand how HMM works, we need to understand how it made of. A complete definition of an HMM requires the following components. A **model** $$\lambda$$ is define as:
$$\lambda = (A, B, \pi)$$

Where:
* **$$A$$**: Transition matrix - we've been introduced in the last section.
* **$$B$$**: Emission matrix - we've been introduced in the last section.
* **$$\pi$$**: Initial state distribution - define the probability of starting in a particular state.

**a. Transition Matrix ($$A$$)**
$$A = \begin{bmatrix} a_{11} & a_{12} & ... & a_{1N} \\ a_{21} & a_{22} & ... & a_{2N} \\ ... & ... & ... & ... \\ a_{N1} & a_{N2} & ... & a_{NN} \end{bmatrix}$$

The transition matrix $$A$$ is a square matrix size $$N \times N$$ ($$N$$ is the number of hidden states.) where each element $$a_{ij}$$ represents the probability of transitioning from hidden state $$i$$ to hidden state $$j$$:

$$a_{ij} = P(q_{t+1} = S_j | q_t = S_i)$$


Since each row is a probability distribution from the state in that row to another states, the sum of each row must be equal to 1.

**b. Emission Matrix ($$B$$)**

This is the connection between the hidden states and the observable emissions. While our goal for HMM is to predict the hidden states from given observations, we need to use the **emission matrix** $$B$$ to define the opposite: probability of emitting a specific observation given a hidden state since we would need that value to fulfill that goal in HMM. 

While the **transition matrix** $$A$$ has $$N$$ rows (one for each hidden state), **emission matrix $$B$$** would be a $$N \times M$$ matrix where $$N$$ is the number of hidden states, and $$M$$ is the number of observations.
$$
B = \begin{bmatrix} b_{11} & b_{12} & ... & b_{1M} \\ b_{21} & b_{22} & ... & b_{2M} \\ ... & ... & ... & ... \\ b_{N1} & b_{N2} & ... & b_{NM} \end{bmatrix}
$$

**c. Initial Probabilities ($$\pi$$)**

Every system needs a starting point. $$\pi$$ is a vector containing the probabilities of starting in each of the $N$ hidden states. For example, on the first day of a semester, you are 80% likely to be a "Happy" student and 20% likely to be a "Stressed" student, then we would have:
$$
\pi = [P(\text{happy}) = 0.8, P(\text{stressed}) = 0.2]
$$

## 2.2. The two Assumptions in HMM
**a. Markov Assumption**

The hidden state at time $t$ depends solely and directly on the hidden state at the time immediately preceding it. Mathematically, this is expressed as:    
$$P(q_t | q_{t-1}, q_{t-2}, ..., q_1) = P(q_t | q_{t-1})$$
This assumption simplifies the model by reducing the dependency of a state to only its immediate past state.



**b. Output Independence**

The probability of an observation $O_t$ at time $t$ depends only on the hidden state $q_t$ at that same time $t$.Mathematically, this is expressed as:
$$P(O_t | O_{t-1}, O_{t-2}, ..., O_1, q_t, q_{t-1}, ..., q_1) = P(O_t | q_t)$$

> **Note**: When we are talking about **Hidden state $q$**, we are assuming that the next hidden state $q_t$ only depends on the current hidden state $q_{t-1}$, not the previous hidden states $q_{t-1}, q_{t-2}, ..., q_1$. On the other hand, when we are talking about **Observations $o$**, we are assuming that the current observation $o_t$ depends only on the current hidden state $q_t$, **not** the **previous hidden states** $q_{t-1}, q_{t-2}, ..., q_1$ or **previous observations** $o_{t-1}, o_{t-2}, ..., o_1$.

# 3. The three problems of HMM
There are 3 problems in HMM we woud need to understand the concept and distinct from each other:
1. **The Evaluation Problem**: 

Calculate the probability an observation sequence $O = (o_1, o_2, ..., o_T)$ to appear when we know the model $\lambda = (A, B, \pi)$. 

In mathematical form, we want to find $P(O|\lambda)$.

2. **The Decoding Problem**: 

Find the most likely sequence of hidden states $Q = (q_1, q_2, ..., q_T)$ when given an observation sequence $O = (o_1, o_2, ..., o_T)$ and the model parameters $\lambda$. 

In mathematical form, we want to find $Q* = argmax_Q P(Q|O, \lambda)$.

3. **The Learning Problem**: Calculate the model parameters $\lambda$ given an observation sequence $O = (o_1, o_2, ..., o_T)$ and the sequence of hidden states $Q = (q_1, q_2, ..., q_T)$. 

In mathematical form, we want to find $\lambda* = argmax_\lambda P(O|\lambda)$.

## 3.1. The Evaluation Problem & The Forward Algorithm
### a. The Evaluation Problem
In the last section, we have been introduced to how HMM work and define the Triplet Parameters (A, B, $\pi$). Now, we will move on to the first classic problem: the Evaluation Problem.

Let's continue with the weather example. 

**Hidden states**
* Hot
* Cold

**Observation**
* 1
* 2
* 3

We have this observation sequence: $O=(3,1,3)$

So the Evaluation Problem asks: **What is the probability for this sequence to be generated from the current HMM?** or in other way: Calculate $P(O|\lambda)$.

So why is this problem is hard? Well, because we don't know what hidden states can lead to that current observations. For example, observation: $O=(3,1,3)$ can be generated by $(Hot,Hot,Cold)$ or $(Cold,Hot,Cold)$ or many other sequences of hidden states.

So if we want to calculate the exact probability of $P(O|\lambda)$, we would have to sum over all possible sequences of hidden states that can generate the observation sequence $O$, then we will have:
$$P(O|\lambda) = \sum_{Q} P(O,Q|\lambda) $$
$$= P(O,Cold, Hot,Cold|\lambda) + P(O,Hot,Hot,Cold|\lambda)+ ...$$

Let's break down the math a little bit, we have:
$$P(O, Q) = P(O \mid Q) P(Q)$$
so:
$$P(O,Q∣λ)=P(O∣Q,λ)P(Q∣λ)$$

1. For $P(Q|λ)$:

We have: $$P(Q|λ) =P(q_1, q_2, ...q_T)$$

$$= P(q_1) \cdot P(q_2 \mid q_1) \cdot P(q_3 \mid q_1, q_2) \cdot ... \cdot P(q_T \mid q_1, ..., q_{T-1})$$

And so for HMM:

$$P(Q|λ) = P(q_1, q_2, ...q_T∣λ)$$

$$= P(q_1 \mid \lambda) \cdot P(q_2 \mid q_1, \lambda) \cdot P(q_3 \mid q_1, q_2, \lambda) \cdot ... \cdot P(q_T \mid q_1, ..., q_{T-1}, \lambda)$$

Due to the Markov assumption in HMM that next state only depends on the current state, so:

$$= P(q_1 \mid \lambda) \cdot P(q_2 \mid q_1, \lambda) \cdot P(q_3 \mid q_2, \lambda) \cdot ... \cdot P(q_T \mid q_{T-1}, \lambda)$$

$$= P(q_1 \mid \lambda) \prod_{t=2}^T P(q_t \mid q_{t-1}, \lambda)$$

$$=\pi_{q_1} \prod_{t=2}^T a_{q_{t-1}q_t}$$
with $\pi_{q_1}$ is the initial probability of the first hidden state $q_1$ and $a_{q_{t-1}q_t}$ is the transition probability from the hidden state $q_{t-1}$ to the hidden state $q_t$.

2. For $P(O|Q,\lambda)$ we have:
$$P(O \mid Q, \lambda) = P(o_1, o_2, \dots, o_T \mid Q, \lambda)$$

$$= P(o_1 \mid Q, \lambda) \cdot P(o_2 \mid o_1, Q, \lambda) \cdot P(o_3 \mid o_1, o_2, Q, \lambda) \dots P(o_T \mid o_1, \dots, o_{T-1}, Q, \lambda)$$

Due to the output independence assumption in HMM, the probability of an observation $o_t$ at time $t$ depends only on the hidden state $q_t$ at that same time $t$, so:

$$= \prod_{t=1}^T P(o_t \mid q_t)$$


3. Combine and we have:
$$P(O \mid \lambda) =  \sum_{Q} P(O,Q|\lambda) $$
$$=  \sum_{Q} P(O∣Q,λ)P(Q∣λ)$$
$$= \sum_{Q} \left( \pi_{q_1} \prod_{t=2}^T a_{q_{t-1}q_t} \prod_{t=1}^T b_{q_t}(o_t) \right)$$

Here is the big problem, if we have $N$ hidden states and $T$ observations, the number of possible hidden state sequences is $N^T$. Simply, we cannot sum over all possible sequences of hidden states when $N$ and $T$ are large. 

There must be a more efficient way to calculate the probability of an observation sequence. That is where the **Forward Algorithm** comes in.

The complexity of brute-force calculation is $O(N^T)$, while the complexity of the forward algorithm is $O(N^2T)$.

### b. The Forward Algorithm
Let's remember how brute-force works, we have to sum over all possible sequences of hidden states, but why is that inefficient?
Let's take an example:

**Hidden states**
* Hot
* Cold

**Observation**
* 1
* 2
* 3

**Tham số HMM ($\lambda$):**

* **Initial probabilities ($\pi$)**
$$\begin{aligned}
P(H) &= 0.8 \\
P(C) &= 0.2
\end{aligned}$$

* **Transition probabilities ($A$)**
$$\begin{array}{c|cc}
\text{From} \setminus \text{To} & \text{H} & \text{C} \\
\hline
\text{H} & 0.7 & 0.3 \\
\text{C} & 0.4 & 0.6 \\
\end{array}$$

* **Emission probabilities ($B$)**
$$\begin{array}{c|ccc}
\text{State} & P(1) & P(2) & P(3) \\
\hline
\text{H} & 0.2 & 0.4 & 0.4 \\
\text{C} & 0.5 & 0.4 & 0.1 \\
\end{array}$$

We want to calculate: 
$$P(O \mid \lambda) = P(3, 1 \mid \lambda)$$

**A — Brute Force**

Since we have 2 timestep and 2 hidden states, we have $2^2 = 4$ possible hidden state sequences: 

1. $$P((3,1) , (H,H)) = P(H,H) \cdot P(3,1 \mid H,H) = P(H) \cdot P(H\mid H) \cdot P(3\mid H) \cdot P(1\mid H)$$

2. $$P((3,1) , (H,C)) = P(H,C) \cdot P(3,1 \mid H,C) = P(H) \cdot P(C\mid H) \cdot P(3\mid C) \cdot P(1\mid C)$$

3. $$P((3,1) , (C,H)) = P(C,H) \cdot P(3,1 \mid C,H) = P(C) \cdot P(H\mid C) \cdot P(3\mid H) \cdot P(1\mid H)$$

4. $$P((3,1) , (C,C)) = P(C,C) \cdot P(3,1 \mid C,C) = P(C) \cdot P(C\mid C) \cdot P(3\mid C) \cdot P(1\mid C)$$

The result would be the sum of all these probabilities.

We can see really clearly that we have to calculate the probability of the same hidden state multiple times.

**B — Forward Algorithm**

The Forward Algorithm idea is only to calculate the probability of an observation sequence in a more efficient way.

**Step 1**: Let's start with time step 1 with the first observation $o_1 = 3$: 

We have 2 possible hidden states: $H$ or $C$. So we have to calculate:
$$\alpha_1(H) = P(3, H) = P(H)P(3 \mid H) = 0.8 \cdot 0.4 = 0.32$$
$$\alpha_1(C) = P(3, C) = P(C)P(3 \mid C) = 0.2 \cdot 0.1 = 0.02$$

**Step 2**: Then, we move to time step 2 with new observation $o_2 = 1$:

To calculate probability of the observation $o_2 = 1$, we see that we have the 2 hidden state H or C can lead to $o_2 = 1$. So, we need to calculate $P(1,H)$ and $P(1,C)$. However, we also need to multiply the previous hidden state probabilities to the current hidden state probabilities. we need to calculate probability of the first step (which might also be H or C, that then lead to observation $o_2 = 1$). So, we need to calculate from the first timestep the $P(1, H) = P(H) \cdot P(1|H)$ and also the $P(1, C) = P(C) \cdot P(1|C)$ to multiply with the probability of the second step. 

> Notice that we already done that by calculating $\alpha_1(H)$ and $\alpha_1(C)$ in Step 1, so we can just reuse it.

Probability to generate H for second step: 
$$\alpha_1(C) \cdot P(H|C) + \alpha_1(H) \cdot P(H|H)$$
Next is probability from H to generate 1: we multiply by $P(1|H)$

And the result for generating observation at second step $o_2 = 1$ from $t_2 = H$ is: $\alpha_2(H) = [\alpha_1(C) \cdot P(H|C) + \alpha_1(H) \cdot P(H|H)] \cdot P(1|H)$

Same as: $\alpha_2(C) = [\alpha_1(C)P(C|C) + \alpha_1(H)P(C|H)]P(1|C)$
